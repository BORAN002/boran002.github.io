EpiAgent: An Agent-Centric System for Ancient Inscription Restoration

Idea

EpiAgent 将古代碑文修复组织为 Observe–Conceive–Execute–Reevaluate 循环，由 Kimi-K2 central planner 根据文字、字形、损伤程度与历史工具经验，为每个字符制定和修改修复序列。系统同时追求 textual authenticity 与 calligraphic fidelity，避免整张图一次修复造成过度修复或风格失真。

Research Problem

碑文具有语义与字形紧密耦合的特征，不同位置可能同时存在背景噪声、缺笔和严重缺字。通用 image restoration 工具不理解古文语义和书法风格，刚性流水线又会传播错误。字符级模型难保证全碑一致，而单一 restorer 难兼顾完整笔画保护与严重缺损重建。

Insight

恢复内容、恢复结构及恢复风格应由不同证据与工具支持。先建立可靠字符布局和文字假设，再按字符损伤自适应安排工具；评价时分别检验 OCR 一致性和风格相似性，才能定位失败字符并有针对性地重规划。历史成功率可提供初始策略，而反馈让策略随实际修复更新。

Method

  1. Observe 阶段用 MLLM 给出初始 layout 与文字 hypotheses。经微调的 Corrective Language Model 结合 Chinese corpus RAG 校正文本，Layout Rectification Module 补齐缺失位置，Degradation Assessment Module 输出 pixel masks 和四档 severity。
  2. Conceive 阶段从历史 execution logs 估计 degradation patterns 对应的 tool-efficacy distributions，planner 联合 observation record 和经验，为每个字符生成有序工具列表。
  3. Execute 提供 diffusion-based background denoising、stroke completion 和 font imitation，分别去噪、局部补笔和利用同碑高质量字符的 style priors 重建字形。Character Retrieval 从原碑查找同字，作为不可恢复字符的替代方案。
  4. Reevaluate 比较 OCR 与 corrected reading 的 CER、当前字形与参考 style embeddings 的 cosine similarity，并可纳入专家接受信号。未达阈值的字符进入新计划，达到标准或迭代预算后停止，最终日志用于更新经验。
