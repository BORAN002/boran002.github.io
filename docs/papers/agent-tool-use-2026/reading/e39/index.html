QBridge: Bridging Natural Language and SQL via Gold Query Rewriting with Agentic Refinement

领域应用 / 数据分析 · 直接工具使用 · 方法 / 系统

官方论文页 ↗PDF ↗文献检索
IdeaResearch ProblemInsightMethodSources

Idea

QBridge 在自然语言问题与 SQL 之间加入 Gold Query：按 SQL clause 顺序组织、仍以自然语言表达的 schema-aware 中间表示。系统先规范化用户意图，再分别审查 rewrite 和 SQL，使语言歧义能够在符号查询生成前被定位和修正。

Research Problem

单次 Text-to-SQL 解码要同时理解含糊问题、关联 schema 和生成严格语法，早期误解会扩散到 joins、conditions 和 aggregations。已有 schema linking 或 SQL repair 多在解码层补救；较形式化的 IR 又可能丢失语言线索，并保留原问题的歧义。

Insight

训练时可用 gold SQL 提供明确语义，把它反向转成经执行验证的自然语言监督；推理时轻量 rewriter 只需问题和 schema，就能继承这种对齐行为。执行成功不能证明意图正确，因此 SQL 修复还需将查询反向解释，与已审核的意图比较。

Method

  1. 定义 Gold Query Norm，按 SELECT、FROM、JOIN、WHERE、GROUPBY、ORDERBY、LIMIT 槽位显式表达 clause semantics。教师读取问题、schema 与 gold SQL 生成 rewrites，再由固定 SQL generator 回译，保留可执行且结果与 gold 一致的样本。
  2. 用上述 Distilled Back-Translation 数据对 student rewriter 做 SFT，使其仅从问题和 schema 产生 Gold Query，推理不依赖 gold SQL 或显式 token-level schema linking。
  3. Rewrite Reviewer 按语义等价、槽位、排序分组、join、条件和 schema 等清单诊断问题，Rewrite Refiner 只执行必要的局部修改，避免补入无依据的属性和条件。
  4. SQL backbone 从审核后的 rewrite 生成候选，结合执行结果与 reverse deduction 的语义差异迭代修正；字符串大小写通过数据库 case-insensitive exact lookup 规范化。以 Spider、BIRD 及鲁棒性变体评估，并统计整个多阶段流程的 tokens、时间和费用。
