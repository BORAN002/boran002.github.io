ToolScope: Enhancing LLM Agent Tool Use through Tool Merging and Context-Aware Filtering

规划 / 记忆 / 工作流 · 直接工具使用 · 方法 / 系统

官方论文页 ↗PDF ↗文献检索
IdeaResearch ProblemInsightMethodSources

Idea

ToolScope 联合处理大工具库中的语义冗余和上下文容量：先通过 ToolScopeMerger 把等价工具聚类、审核并规范化，再用 ToolScopeRetriever 按查询分解和重排序只提供有限相关候选。它将工具集合的治理与逐题检索连成一个流程。

Research Problem

名称和描述相近、功能重叠的工具会混淆 retrieval 与 LLM selection；直接给出整个工具库又超出 context window。已有方法多改写单个文档或做检索，未系统消除库内重复；多子问题检索的原始分数还可能不可直接比较，导致某个子目标的工具挤占所有候选。

Insight

先降低候选之间不必要的语义歧义，再进行上下文压缩，可同时改善工具辨识与预算使用。图连通分量可高效提出合并簇，但近似等价关系可能传递错误，因此需要簇级复核；多任务检索则应先保证每个子问题的最佳工具，再全局补充。

Method

  1. 对工具 signature 和 description 编码，检索 top-k 相似工具作为候选对；LLM 二分类判断功能等价，建立无向 pruning graph，并提取 connected components。
  2. 每簇选函数名较短的代表工具；可选 Auto-Correction validator 检查全簇是否等价，将错误簇拆分或移除不匹配成员，再作完整性检查，维护原工具到规范工具的映射。
  3. LLM 生成合并后的 signature 与 description，并依映射重标 benchmark 中目标工具；该步骤改变候选工具空间，保障后续查询标签与合并工具一致。
  4. Retriever 对查询/子查询组合 sparse 与 dense similarity，cross-encoder rerank；多工具场景先保留各子查询 top-1，再对剩余分数做 min-max normalization，全局补齐 top-k 候选供代理选择。
