A Multi-Agent Framework for High-Interaction Terminal Simulation

Idea

MANTIS 将高交互 terminal simulation 拆成命令路由、状态维护与输出生成，通过真实状态快照和 state-aware history pruning 保持多轮一致性。简单只读命令由确定性 handler 响应，复杂状态变更交给分工代理处理，使终端输出既遵守格式又能追踪文件、权限和会话变化。

Research Problem

脚本模拟器难覆盖复杂交互，单个 LLM 则容易误解 shell 语义、编造输出或忘记早期状态，还可能被 prompt injection 拉离终端角色。普通摘要或最近历史截断会丢失路径、权限、工作目录等细节，这些细节又直接决定后续命令行为。

Insight

模拟终端需要保存因果状态，而不只是像终端的文字。将系统 snapshot 与完整持久日志独立于有限上下文维护，再优先保留产生关键状态变化的命令，可以在控制上下文大小时保留后续执行依赖。路由也使不同命令采用适合的执行机制。

Method

  1. Arbiter 记录执行前后 snapshot、system/session/authentication logs，并用 routing model 分类 Read、Write、Rejection；Read 调用状态读取 handler，非法或注入输入返回 shell 风格错误。
  2. Write 交给 Strategic Agent 处理必要历史和状态上下文，可选地生成 honeypot 场景响应计划；系统更新 snapshot 与精简历史后，Response Agent 根据当前状态和计划生成输出并记录 trace。
  3. Agentic file system 以统一命名空间保存各类上下文工件；上传和修改文件进入专用 Docker sandbox，仅记录内容与结构变化，隔离宿主执行和外网访问。
  4. History pruning 始终保留完整持久历史，但限制模型可见窗口；按重复命令、状态变化等级和时间老旧程度依次选择淘汰记录，优先保护权限身份、持久配置等关键变化，支持长时状态连续性。
