FS-Researcher: Test-Time Scaling for Long-Horizon Research Tasks with File-System-Based Agents

搜索 / 检索 / Deep Research · 扩展相关 · 方法 / 系统

Idea

FS-Researcher 通过 persistent file-system workspace 协调 Context Builder 与 Report Writer：前者搜集网页、归档 sources 并建设结构化知识库，后者只基于知识库逐节写作。跨 session 的进度和证据保存在文件中，使 research effort 能超过单次 context window。

Research Problem

Deep Research 同时消耗 evidence collection 与 long-form writing 的 context budget；单 agent 或只做历史摘要容易过早写作、遗漏事实，难以继续增加有效 computation。论文研究如何把知识积累和报告生成分离，并让多轮工作保有稳定、可检查的进度与事实来源。

Insight

外部存储的价值不只是容纳更多文本，还在于显式维护 task state、evidence provenance 和待补缺口。独立的 Context Builder 可以持续改善知识库，而 section-wise writing 则让每节重新基于证据规划。其可扩展性是总 workspace 跨 session 扩展，并不是模型获得无限 context window。

Method

  1. 为两种 ReAct agents 提供 ls、grep、分页 read_file、按行编辑以及 web search/read tools；workspace 包含 deliverables、动态 todos、人工制定的 checklists 和 session logs。每轮先检查状态，再执行与复核。
  2. Context Builder 动态维护 index.md、层级 knowledge_base 和 raw sources；notes 的事实引用对应 source files。每次 session 结束根据 checklist 找缺口或冲突并重新标记待办，直到完成或用尽 session budget。
  3. Report Writer 接手后移除 web browsing tools，以知识库为唯一事实来源；先建立 outline，之后每轮只写一节，通过 section review 才标完成，最后进行全篇 review，并可重新打开有问题的章节。
  4. 通过 DeepResearch Bench、DeepConsult 评价报告，另对 persistent workspace、dual-agent 和 section-wise writing 做 ablation；scaling 分析比较 3/5/10 个 Context Builder rounds。Writer 阶段未设预算上限，因此比较成本时需保留这一协议差异。
