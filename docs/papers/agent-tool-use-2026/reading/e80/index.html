Spatial-Agent: Agentic Geo-spatial Reasoning with Scientific Core Concepts

多模态感知与创作 · 直接工具使用 · 方法 / 系统

官方论文页 ↗PDF ↗文献检索
IdeaResearch ProblemInsightMethodSources

Idea

Spatial-Agent 将自然语言地理问题转换成受 GIScience core concepts 与 functional roles 约束的 GeoFlow Graph，再映射为实际 GIS operators 执行。核心改变是在自由文本规划与工具调用之间加入可检查的空间类型和依赖表示，使回答建立在地理计算结果上。

Research Problem

ReAct 等通用 agent 可能把地理关系当成语言相似性，混淆实体范围、拓扑和计算顺序，例如先聚合再施加本应限定统计空间的条件。即使知道某个 API，也未必能补齐隐含的 road network、route 等中间对象，并组成输入输出类型兼容的可执行流程。

Insight

空间问题具有重复的概念转换结构，不能只靠语言常识排列操作。区分实体是什么与它在分析中起什么作用，能够同时约束类型和先后关系；再把抽象概念依赖展开成多输入 operator，才可以从解释性规划走到真实执行。

Method

  1. 从问题抽取 Location、Object、Field、Event、Network、Amount、Proportion 七类 core concepts，并赋予 Extent、Temporal Extent、SubCondition、Condition、Support、Measure 等角色；区分限定数据范围的 contextual roles 与需遵循先后关系的 procedural roles。
  2. 从预验证 macro-template library 和 question–graph store 检索相关转换子图与例子，补齐隐含节点，构造 GeoFlow Graph；检查 acyclicity、role ordering、type compatibility、data availability、connectivity 五类约束。
  3. 将概念图 factorize 为 operator–concept hypergraph，显式补入距离等执行参数与多输入依赖，映射 geocoding、spatial search、routing、geometry、trip optimization 工具，按拓扑顺序执行并保存所有中间结果供回答生成。
  4. 框架可直接 prompting 使用，也提供可选 SFT→DPO：先学习概念类型和角色抽取，再以符合全部约束的图相对于违规图构造 preference pairs。用 MapEval-API 与 MapQA 比较通用 planning agents，覆盖地点、邻近、路线和行程分析。
