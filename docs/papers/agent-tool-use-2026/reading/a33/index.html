Idea

PFUA 将蛋白功能问答的推理与领域工具交错：LLM 分解问题、按需要获取 sequence statistics、homology、domain 和 membrane topology evidence，再修订功能假设并生成解释。核心改变是让推理获得新的生物证据，而非仅延长文本 CoT。

Research Problem

作者的 R1-style SFT/GRPO pilot 在蛋白问答中容易学高频术语以获得部分词汇奖励，随后收益平台化。序列到生物功能是知识密集问题，单靠内部语言推导难补足进化关系、结构约束或 curated annotations，直接套用数学 reasoning 训练因此受限。

Insight

不同工具在不同层次限制候选：基础统计做 sanity check，Pfam 限定 fold/domain 家族，TMbed 约束定位，homology 提供具体功能参考。将这些结果视为可审计证据并相互检查，比把某个 domain hit 直接等同精确功能更符合生物推断需求。

Method

  1. 通过统一 executor 暴露四类工具；basic-properties 计算长度、最长 hydrophobic run 与 low-complexity index，用于识别膜相关或重复序列等早期线索。
  2. MMseqs2 搜索 curated Swiss-Prot，按 E-value/bit-score 等确定 best hit，再抽取 FUNCTION、catalytic reactions、EC、cofactor、location 和 GO 的结构化证据。
  3. 用 Pfam-A HMM scan 获取显著 domain hits、边界、coverage 和 confidence，将其用于机制/架构假设；TMbed 输出 residue-level topology 与膜相关性，辅助 localization/GO 判断。
  4. 在线 LLM 根据问题和已有输出逐步选择工具、更新假设并形成回答，比较 text-only、一次附加 multi-source RAG 与 interleaved tool-powered 设置。
  5. 在 Mol-Instructions、UniProtQA、PDB-QA 和 CAFA 上评估，主指标采用 reference-normalized ROUGE recall，并对原 text reasoning pilot 与工具结果作分析。
