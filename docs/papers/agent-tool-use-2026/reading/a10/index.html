ACE-Router: Generalizing History-Aware Routing from MCP Tools to the Agent Web

规划 / 记忆 / 工作流 · 直接工具使用 · 方法 / 系统

官方论文页 ↗PDF ↗文献检索
IdeaResearch ProblemInsightMethodSources

Idea

ACE-Router 训练能够读取当前 observation 与完整交互历史的候选选择器，以独立 routing/execution 接口接入 MCP agents。其数据管线用工具关系图与受控 mutation 合成互相相近、存在依赖的候选，再由多角色模拟生成 history-aware 路由监督。

Research Problem

将全部 tool schemas 注入主 agent 随候选增多而饱和；embedding retrieval 只比较 query 与描述，难区分同功能工具在任务不同阶段是否适用。现有孤立 query–tool pairs 又缺少前置调用结果和多步依赖，无法训练动态状态下的精确选择。

Insight

路由的语义单位应是“此刻任务需要的下一种能力”，而不是原始用户问题的静态相似度。让训练候选包含近似功能和依赖关系，并从连续轨迹中抽出状态–候选配对，可迫使 router 利用历史；同一选择问题可从工具描述迁移到 agent profiles。

Method

  1. 将 candidate description/schema 编码，按 cosine threshold 建立相似图；通过 function enhancement、parameter mutation、workflow chaining 等算子产生相关新候选，并保留 mutation edges。
  2. 从图的 seed nodes 作邻域遍历采样关联候选子集，Planner 设计任务与计划，User、Assistant、Tool roles 模拟多轮对话和执行结果，整个合成不依赖真实 API。
  3. 抽取每个 candidate invocation 作为标签， preceding interactions 为 history、最近 observation 为当前 query，形成 router 训练样本；在 Qwen3-8B 上以 LoRA 微调。
  4. Light Routing Agent 只暴露 router invocation 与 execution 两个接口，前者根据历史从给定候选空间选择能力，后者执行并把结果接回任务，减少主 agent 的 schema 上下文负担。
  5. MCP-Universe/MCP-Mark 固定下游 Gemini reasoner 比较 routers，并在独立 agent-bank 合成测试及大候选/噪声设置检验迁移；工具选择训练不额外用 agent-routing 数据微调。
