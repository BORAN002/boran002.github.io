IntrAgent: An LLM Agent for Content-Grounded Information Retrieval through Literature Review

搜索 / 检索 / Deep Research · 直接工具使用 · 方法 / 系统

官方论文页 ↗PDF ↗文献检索
IdeaResearch ProblemInsightMethodSources

Idea

IntrAgent 面向 IntraView：只根据给定 scientific paper 回答细粒度研究问题，先利用 section hierarchy 推理相关位置，再逐节提取证据并检查充分性。它将阅读过程显式分为结构定位和证据积累，避免把整篇文献压给模型或只按 chunk embedding similarity 找答案。

Research Problem

实验参数、样本定义和技术细节可能分散在多个不相邻 sections，也可能根本没有报告。普通 RAG 的表面相似匹配容易取错相关但非目标情境，全文 prompting 又被冗余信息干扰。开放 literature-search agent 的目标与这里仅忠实提取指定内容不同，可能引入外部知识或生成式补全。

Insight

论文标题层级本身携带“信息通常出现在哪里”的结构先验，LLM 可以利用它排序阅读顺序；逐条将细节锚定到原句，并在每轮检查是否充分，能让跨章节综合与缺失信息识别成为明确操作。这里的可靠性来自可追溯证据和阅读控制，而不是对论文科学结论的外部验证。

Method

  1. 用 MinerU 将 PDF 转成 Markdown，提取 headings，再让 LLM 恢复 parent–subsection hierarchy；删除无实际内容的冗余父节点路径，形成可对应原文 text 的 section tree。
  2. 给定问题和过滤后的标题集合，让 LLM 推理并输出 section relevance ranking，将全文重排为 heading/text pairs，按优先级读取而不只依赖 dense retrieval。
  3. 循环执行 section access、detail extraction、sufficiency check；记录术语、数值、实验设定等与原句对应的 details 到短期记忆，信息不足继续下一节，足够后用累计证据合成简洁答案。提供控制阅读量的三种 confidence styles。
  4. 构建五个 STEM 领域共 315 个 expert-authored instances，每域从专家熟悉文献池随机选五篇。系统生成 free-form short answer 且看不到选项，评价 LLM 将答案映射到专家设计的六选项，无法对齐则归 None of the above，最终以映射 accuracy 比较多 backbone 和 RAG/agent baselines。
