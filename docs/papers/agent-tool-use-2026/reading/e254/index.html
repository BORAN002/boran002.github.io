PExA: Parallel Exploration Agent for Complex Text-to-SQL

Idea

PExA将复杂Text-to-SQL视为收集语义测试证据后再合成完整查询的问题。Planner设计独立的探索性SQL tests，Test Case Generator并行执行并修正，SQL Proposer只使用这些提炼后的证据构造最终SQL；并行性同时用于规划、执行与单次生成中的多路径候选，以改善准确率和等待时间的折中。

Research Problem

企业数据库含大量列、嵌套类型与长查询，直接生成SQL容易遗漏过滤、join或aggregation语义。传统agent通过串行工具调用和self-correction提升成功率，却把推理及数据库等待逐步累加；普通query decomposition只处理题内子问题，也可能错过用于辨别schema和值分布的外围信息。

Insight

独立的小SQL能探查表结构、取值和中间结果，形成可执行的局部证据；这些探查不必完全局限于用户题目中的直接子句。先扩大证据覆盖，再集中合成，可以减少最终生成的schema噪声；相互独立的探索还允许并发执行，使等待更接近最慢路径而不是所有路径之和。

Method

  1. Planner在单次生成中提出多种自包含test case，覆盖过滤、连接、聚合、存在性及相关外围信息，并决定继续探索还是将已收集证据交给Proposer。
  2. Test Case Generator先做偏重recall的schema linking与database compression，针对每个test一次生成多种SQL候选；并发执行tests，根据编译错误、空结果或成功结果修正探索。
  3. Proposer接收原问题及已执行tests，不接收完整database metadata，组合局部证据生成最终长SQL；SQL Executor检验执行，Semantic Verifier把SQL反译为自然语言后与原题比较，Planner最终审查。
  4. 在Spider 2.0-Snow和排除BigQuery的Lite*上评估Execution Accuracy、EX@4及平均wall time，并通过移除并行规划、并行测试、verifier与Proposer做消融；主系统还用四次运行的majority consensus做inference-time scaling。
