RISK: A Framework for GUI Agents in E-commerce Risk Management

安全与可靠性 · 扩展相关 · 方法 / 系统

官方论文页 ↗PDF ↗文献检索

Idea

RISK 将电商风险信息检索的真实浏览流程组织为专用数据、benchmark 与 RFT 配方。RISK-R1 直接学习 Browser Use 的 DOM index/tool-call 形式，结合响应格式、动作列表正确性、轨迹位置和任务难度调整 GRPO 训练。

Research Problem

静态 crawler 难处理交互后才出现的信息，通用 GUI 训练又多用坐标 bbox reward，与实际 Browser Use 的 DOM 元素和复合工具列表不一致。一次响应含多个动作时全对才奖过于稀疏，而只给部分正确奖励又可能让模型停留在不完整执行。

Insight

训练信号应匹配部署动作表示，并在早期提供细粒度探索信号、后期要求完整列表正确。电商流程后段网页往往更复杂且更有任务差异，位置与难度权重因此把学习资源移向难点；这是基于离线参考动作的 RFT，不等于在线端到端风险判断得到监督。

Method

  1. Qwen-VL-Max 在 Browser Use 中按领域模板执行 information search 和 website verification，记录截图、DOM、历史与动作；过滤失败轨迹、清理冗余步骤、整理上下文、改写问题并串接多步序列。
  2. 以强模型每题五次表现分 easy/moderate/difficult，得到 RISK-Data 的 8,492 单步和 2,386 多步轨迹；RISK-Bench 保留 802/320 条并从训练排除。
  3. Qwen2.5-VL-7B 先 SFT 学 thinking、evaluation_previous_goal、memory、next_goal 与工具列表结构；RFT 仅用单步轨迹并混入 GUI-R1，因为完整多步输入过长，不能把此阶段称为整轨迹 online RL。
  4. format reward 检查结构，早期对列表各 tool call 与 gold 的 F1>0.5 指示求平均，后期改为整列表二元正确性；用随原轨迹步骤递增的 process weight 加重后段，再按难度 level weight 缩放 GRPO objective。
  5. 分别做离线 RISK-Bench/OS-Genesis 和真实网页在线测试。离线单步按 tool-call F1 阈值，离线多步要求全部调用正确；在线区分 20 步内结束的 completion 与答案正确的 success。
