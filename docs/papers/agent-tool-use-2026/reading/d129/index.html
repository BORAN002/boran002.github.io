KoCo-Bench: Can Large Language Models Leverage Domain Knowledge in Software Development?

代码 / 软件 / 科研执行 · 扩展相关 · 评测 / 分析

官方论文页 ↗PDF ↗文献检索
IdeaResearch ProblemInsightMethodSources

Idea

KoCo-Bench把domain-specific coding评测改为显式提供知识语料后，测试模型能否获取并应用新框架知识。它将framework文档、源码和examples组成Knowledge Corpus，再用依赖这些框架的项目构建多粒度代码生成及知识Q&A任务，支持比较SFT、RAG、kNN-LM和coding agents等不同specialization方法。

Research Problem

已有领域代码benchmarks常只给测试题，实际测模型预训练时已掌握多少知识，无法可靠评价适应新领域的方法。同领域项目之间知识重叠可能很弱，简单train/test函数拆分也不能保证训练资料足以支持任务；code completion和文本相似度还容易把多种有效答案混为错误。

Insight

软件框架与基于其实现的项目天然具有知识复用关系，因此能建立来源清晰的知识—任务配对。把要求写成领域问题，再通过执行tests判断实现，既可检验理解API、规则和约束，也能减少仅靠记忆代码片段的评价方式；独立Q&A则帮助观察知识掌握与代码应用的差异。

Method

  1. 围绕较新的框架收集documentation、source和usage examples，构建涵盖六域、11 frameworks的知识语料；选取主要依赖对应框架且满足依赖时间要求的25个项目作为代码任务来源。
  2. 人工按project、module和core function三层写需求，排除config/utils等通用辅助逻辑；agent尝试实现以暴露歧义，再经人工和另一agent反复审订，直到需求清晰。
  3. 复用或新建unit tests及integration tests；新测试覆盖函数branches并运行gold code产生expected outputs，对无明确输入输出的函数instrument调用顺序，所有测试在相应Docker环境验证。
  4. 对缺少合适项目的框架构造领域multiple-choice Q&A，先人工示范、模型扩展，过滤三种基线都轻松答对的题并人工复核；分别用执行测试与选择题正确率评估知识获取、应用及不同specialization方法。
