GATE: Graph-based Adaptive Tool Evolution Across Diverse Tasks

规划 / 记忆 / 工作流 · 直接工具使用 · 方法 / 系统

官方论文页 ↗PDF ↗文献检索
IdeaResearch ProblemInsightMethodSources

Idea

GATE 将可复用程序工具组织为分层 Tool Graph，用 GraphRank 同时考虑 docstring 语义和调用结构来检索。Task Solver 与 Tool Manager 根据任务创建、组合、合并和剪枝工具，使经验积累为有依赖关系的技能库，而非不断增加独立脚本。

Research Problem

现有 tool-making 常一题生成一个工具，造成重复库和检索成本；固定创建规则或只支持简单 wrapper 又限制复杂技能复用。纯语义检索忽略某工具作为高层组合依赖的作用，按频率机械删除则可能破坏稀少但重要的复杂能力。

Insight

工具的价值同时来自功能相关性和在组合中的位置。显式存储 invocation relationships 能引导相关模块共同检索，并在合并或剪枝时保护依赖；只从成功任务吸收实际使用的工具，减少未经任务验证的候选污染长期库。

Method

  1. 节点保存 name、docstring、code、usage frequency 与层级，basic tools 为底层，composed tools 层级由调用依赖决定；检索图用无向边记录双方是否存在调用。
  2. GraphRank 以 query–docstring cosine similarity 的归一化分布作为先验，结合工具图上的 PageRank-style 随机游走，取 top-k 供 Solver/Manager 使用。
  3. Task Solver 提出功能需求，Manager 检索、复用或扩展工具并 self-check 可复用性、创新、边界条件与实现可靠性；用 Smith–Waterman structural similarity 找重复并合成功能更一般的新工具。
  4. 仅成功解题所用工具进入图并更新调用边，移除被替代冗余工具但保留仍被高层调用者；定期按任务数量、使用率及层级剪枝，高层阈值更低且保留其全部依赖。
  5. Minecraft 采用在线构建与探索；封闭代码/agent tasks 在训练任务上建库、剪枝，测试时冻结 tool graph 并用检索增强推理，区分经验库演化与模型参数训练。
