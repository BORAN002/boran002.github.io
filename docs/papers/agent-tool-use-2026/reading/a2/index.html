COMPASS: Enhancing Agent Long-Horizon Reasoning with Evolving Context

Idea

COMPASS 将 long-horizon agent 的执行、战略判断和 context 整理交给 Main Agent、Meta-Thinker 与 Context Manager。Main Agent 持续运行 ReAct loop；Meta-Thinker 发现循环、tool misuse 或完成信号时介入；Context Manager 根据这些信号重建下一阶段的 brief，让 agent 保留关键证据而不必反复携带全部历史。

Research Problem

长任务中的局部错误会累积，但统一 context 既承担执行记录又承担反思，关键约束容易被冗余 tool outputs 淹没。增加 planner 或 reflector 也未必解决问题：agent 仍须判断何时坚持、何时 pivot，以及何时停止或继续核验。论文研究如何在无需人工战略干预的前提下，使 context 更新与这些决策协同。

Insight

Context management 的价值不只在压缩 token，而在于为下一阶段提供与当前战略决策一致的信息。Meta-Thinker 提供改变方向的触发信号，Context Manager 保留成功尝试、失败路径和未解决问题，二者分别缓解盲目坚持与遗忘。正文的 ablation 支持这种互补性，同时说明过度 revision 也会增加执行成本，不能把更频繁的反思直接等同于更可靠。

Method

  1. 初始化：Meta-Thinker 根据 query 形成初步计划与 notes；Context Manager 将 query、已有结构化 notes 和当前战略信息组织成 Main Agent 的工作 context。
  2. 执行与监控：Main Agent 在 inner loop 中生成 thought、tool call 和 observation；Meta-Thinker 异步检查当前 turn 的轨迹，遇到异常或完成信号后发出 replan、verify 或 stop 等高层决策。
  3. Context refresh：发生介入后，Context Manager 综合轨迹、相关历史 notes 和战略信号生成新 brief，把关键观察及失败经验写回持久 notes；随后进入下一轮，或由 Answer Synthesizer 汇总结果。
  4. 扩展与验证：Context-12B 先用强模型生成的 briefs 做 SFT，再按后续任务成功与 token 使用构建 DPO preference；COMPASS-TTS 探索 parallel sampling。核心系统在 GAIA、BrowseComp 与 HLE 的文本设置中评估，并检查 persist、pivot、conclude 与 error recovery 行为。
